# Vibra Docs

Decision-making repo for **Vibra**, a music streaming demo (native iOS app + ASP.NET Core 11 backend) built for an iOS course. This repo contains **Markdown only**: no application code, no build, no tests. Decisions are made here first. Once everything is decided, the work is broken into sprints and exported as Markdown task files (in Spanish).

## Project snapshot

- Two ways to listen: **subscription** (monthly/annual, full catalog) or **purchase** of a track/album (perpetual access). Payments are **simulated**.
- Tagline: *Todo el catálogo, o solo lo que amas.*
- Stack: SwiftUI, Swift 6, StoreKit 2, AVFoundation, WidgetKit/ActivityKit, ASP.NET Core 11, PostgreSQL via Dapper + Npgsql (**no EF Core**), BindSharp (Result pattern), Valkey (optional cache), FFmpeg, OpenAPI.
- The course requires 3 native iOS tools: StoreKit 2, AVFoundation + MediaPlayer, WidgetKit + ActivityKit.

## Decision workflow

- Each decision records: context, options considered, choice, consequences. Status is `Decided`, `Open` or `Rejected`.
- **Never silently change a `Decided` item.** Propose the change and ask first.
- Open questions go in an explicit pending list, not buried in prose.
- Mark anything not verified as **"to verify"** (the draft does this for free Apple account limits). Do not present guesses as facts. For versions, pricing or Apple/Microsoft behavior, check current sources.
- Keep decisions consistent with the sibling `CLAUDE.md` files and flag drift.
- Recommend one option when asked to choose; do not dump a survey.

## Decided (summary)

Modular monolith · PostgreSQL with Dapper/Npgsql (raw SQL) · audio in private object storage + CDN, never in the DB and never through the API · **FLAC** as main format, 30 s AAC previews · REST/JSON + OpenAPI with generated Swift client · ASP.NET Core Identity + short JWT + rotating refresh tokens (email/password) · MVVM + repositories with local Swift packages, Swift 6 strict concurrency · entitlements computed in the backend (`IEntitlementService.CanPlay`), `403` + `previewUrl` when not entitled · payments simulated with **StoreKit 2 + local `.storekit`** behind `IPaymentGateway` (backend trusts the client in demo mode only; document as a known limitation) · multi-repo layout · name **Vibra**.

**Rejected:** microservices, gRPC/GraphQL, APNs push, Sign in with Apple, CarPlay (all avoid paid-account or special-permission dependencies), backend-side fake payment gateway (option A).

Also decided: **DbUp** migrations · **Cloudflare R2 + CDN** for audio, **Hetzner VPS** for the backend · lossless FLAC for everyone (no tiers) · Xcode Simulator only · latest iOS as minimum.

**Also rejected:** lossless as subscriber-only tier, AAC "Normal" quality.

**Ideas, not decisions:** HLS, SignalR "now playing" sync, App Intents.

### Sprintmodus import format

Output **only the file content**: no explanations, no surrounding code fences. All text in Spanish.

- Each item is a heading with its type followed by the title: `Épica:`, `Característica:`, `Elemento del backlog:` or `Tarea:`. Heading level (`#`, `##`, `###`, `####`) gives the hierarchy: Épica → Característica → Elemento del backlog → Tarea.
- Right below the heading, an optional list of `- clave: valor` lines: `prioridad` (baja | media | alta | crítica), `puntos` (backlog items only), `horas` (tasks only), `sprint`, `asignado`.
- The text that follows is the description.
- `**Criterios de aceptación**` with a list of `- [ ] criterio`, only on features and backlog items.
- Everything is optional except the title. Do not write status or identifiers.
- A backlog item may list tasks inline under `**Tareas**` as `- Title [3h]` (hours optional), or as `####` task headings.
- Optional HTML comments are allowed as notes.
