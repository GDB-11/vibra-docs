# 011 — Multi-repo layout

**Status:** Decided

## Context
Backend, iOS app, contract, DB and docs evolve at different paces. Each repo has its own `CLAUDE.md` with implementation rules; this repo records the *why*.

## Choice
| Repo | Contents |
|---|---|
| `vibra-backend` | `src/Vibra.Api` (host), `src/Modules/{Identity,Catalog,Library,Streaming,History,Search,Billing}/`, `src/Vibra.Worker`, `tests/`, `scripts/export-openapi.sh`, `scripts/sync-db.sh`, Aspire AppHost if used (on Podman, [016](016-podman-containers.md)); the compose file now lives in `vibra-db` |
| `vibra-ios` | `Vibra/` app target, `Packages/` (see [008](008-ios-mvvm-local-packages.md)), `Vibra.storekit`, `scripts/sync-contract.sh` |
| `vibra-contracts` | `openapi.json` (generated by backend CI), `CHANGELOG.md`, `.spectral.yaml`; semver tags |
| `vibra-db` | Everything database related: DbUp migrations per module, seed SQL, Postgres/Valkey compose + init scripts, schema docs ([002](002-postgres-dapper-npgsql.md)); synced into the backend by `scripts/sync-db.sh` |
| `vibra-docs` | Decisions, later sprint exports |

**Contract workflow:** backend change merged → backend CI exports spec and opens PR in `vibra-contracts` → review `oasdiff` + CHANGELOG → merge and tag → in `vibra-ios` run `./scripts/sync-contract.sh` and rebuild.

## Consequences
- CI/CD: GitHub Actions for backend; Xcode Cloud or Actions for iOS.
- Earlier monorepo layout in the draft was replaced by this decision.

## Open items
